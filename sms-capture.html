iPhone Shortcuts — smart purchase particulars

Keep the existing Message automation and capture token. After the first capture request, add a quick purchase-description chooser so each payment can be remembered without changing the bank SMS parser.

  1. Keep the existing trigger: Shortcuts → Automation → Message. Filter to bank transaction alerts only. Never forward OTP, login, balance-only, or promotional messages.
  2. Keep the first Get Contents of URL action: POST to https://magxbczgrxeypryjborr.supabase.co/functions/v1/sms-capture/capture, with the same Bearer token and JSON body containing message mapped to the incoming Message variable and sender mapped to Sender/From when available.
  3. From the first response, get the dictionary value status. If the response has duplicate: true or status: duplicate, stop this automation branch so a duplicate never asks for purchase details.
  4. For posted or needs_review, get the response dictionary values suggested_particulars, inbox_id, and merchant. The suggestions include saved labels for that merchant first, followed by common descriptions.
  5. Add Choose from List and pass suggested_particulars as its input. Use a prompt such as “What did you buy at [merchant]?” (or “What was this payment for?” if the merchant is blank). Existing labels such as Groceries, Dairy Products, Vegetables, and Medical Supplies are one-tap choices.
  6. If the selection is Other, add Ask for Input and enter a short description. If the selection is Skip for now, stop without making the second request.
  7. For any other selected or typed description, add another Get Contents of URL: URL https://magxbczgrxeypryjborr.supabase.co/functions/v1/sms-capture/particulars, Method POST, with the same Authorization: Bearer YOUR_GENERATED_TOKEN and Content-Type: application/json headers.
  8. Set the second request body to JSON with inbox_id mapped to the first response's inbox_id, and particulars mapped to the selected or typed description. The response should contain ok: true.
  9. Test one new merchant, then use it again with a different description. For example, Raj Market can remember both Groceries and Dairy Products. The system keeps the raw SMS particulars separately and learns each selection for that merchant.

The first request still captures the transaction immediately when the bank details are confidently parsed. If the transaction needs review, the selected description is saved with the inbox record and copied into Cash Book when you approve it. If iOS does not show the chooser from a background automation, the transaction remains captured and you can add the particulars later using the Cash Book edit action.

Token security: Never share or screenshot your token. Exposed tokens should be revoked and replaced. Do not forward OTP/authentication SMS.
