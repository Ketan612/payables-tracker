iPhone Shortcuts — daily particulars review

Keep your existing Message automation unchanged: it captures bank SMS into Payables Tracker automatically. Do not add a purchase-description prompt to every incoming SMS. Create a separate daily time-based automation that reviews all transactions still missing particulars and submits the selected descriptions in one batch.

  1. Open Shortcuts → Automation → New Automation → Time of Day. Choose your preferred daily time, set Repeat to Daily, and select Run Immediately if your iOS version offers that option.
  2. Add Get Contents of URL with URL https://magxbczgrxeypryjborr.supabase.co/functions/v1/sms-capture/pending-particulars, Method POST, and headers Authorization: Bearer YOUR_GENERATED_TOKEN and Content-Type: application/json. Use an empty JSON body {}.
  3. Get the response dictionary value items. If count is zero, show “No transactions need particulars today” and stop.
  4. Create an empty list variable named BatchItems. Add Repeat with Each using the returned items.
  5. Inside the repeat, show the merchant, amount, date and debit/credit direction. Add Choose from List using that item's suggested_particulars. Use a prompt such as “What was this payment at [merchant] for?”.
  6. If the selection is Other, use Ask for Input to collect a short description. If it is Skip for now, do not add this item to the batch and continue to the next transaction.
  7. For every selected or typed description, create a Dictionary with two keys: inbox_id (the current item's inbox_id) and particulars (the selected or typed description). Use Add to Variable to append that dictionary to BatchItems.
  8. After End Repeat, if BatchItems is empty, stop. Otherwise add one final Get Contents of URL with URL https://magxbczgrxeypryjborr.supabase.co/functions/v1/sms-capture/particulars-batch, Method POST, the same headers, and JSON body containing one key items whose value is BatchItems.
  9. Read the response values succeeded, failed and results. Show a summary such as “Saved 8 particulars; 1 needs retry”. If any item failed, retain its inbox ID and error so you can retry that item in the next run.
  10. Test with two different transactions from the same merchant. The saved labels should appear first next time, and selecting a different label for that merchant adds another remembered purchase type.

The pending list includes posted SMS transactions and SMS records awaiting manual review, but excludes duplicates, ignored records and transactions already labelled. Skipped items remain pending for the next daily run. Batch submission is one request; the response reports each item separately so a partial failure can be retried without redoing successful selections.

Token security: Use the same generated iPhone capture token. Never share or screenshot it. Revoke and replace any exposed token. The original SMS automation must never forward OTP, login, balance-only, or promotional messages.
